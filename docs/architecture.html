Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI service backed by in-memory JSON data.

System architecture

Three layers, no database. All state lives in the server process memory and is reset on restart.

Data flow

What happens when a user changes a filter on the dashboard.

  1. User picks a filter (period, warehouse, category, status) in FilterBar. State is held in module-level refs in useFilters, so it is shared by every view.
  2. View requests data. The view calls getCurrentFilters() and passes the result to a method in api.js. Values equal to all are omitted from the query string.
  3. Axios sends a GET to http://localhost:8001/api/...?warehouse=&category=&status=&month=. The base URL is hard-coded.
  4. FastAPI filters in memory. apply_filters matches warehouse, category, and status. filter_by_month matches a month or expands a quarter such as Q3-2025 into three months.
  5. Response is validated by the Pydantic response_model and returned as JSON. The dashboard summary is computed on the fly (inventory value, low-stock count, pending orders).
  6. View renders. Raw results go into refs, and charts and totals are derived with computed properties.

Things to know

Gaps found while reading the code.

Mismatches between frontend and backend
  • api.js calls /api/tasks (GET, POST, DELETE, PATCH) and /api/purchase-orders, but main.py defines no such routes. Only the Pydantic models for purchase orders exist.
  • Backlog.vue exists but is not registered in the router in main.js.
  • User and task data in useAuth is mocked on the client; there is no real authentication.
  • CORS allows all origins and the API base URL is hard-coded to localhost, so both need changing before any real deployment.
  • Month and quarter filtering is a substring match on order_date and is hard-coded to 2025.
